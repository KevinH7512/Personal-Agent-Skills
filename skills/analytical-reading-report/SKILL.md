# 分析化学小班读书报告

目标是写出一篇读懂论文、解释实验设计、能就具体证据提出独立意见的中文课程报告。风格基准来自用户提供的原子光谱、红外、拉曼、荧光四篇独立报告。教师批注是对用户原 Word 报告的意见和评论，仅帮助理解写作反馈，不属于报告正文、格式组成或新论文的事实来源。

## 读取与交付范围

- 写作前读取 [栏目与风格](references/style-guide.md)。涉及定量推导、谱图、拟合或机制判断时，读取 [证据与计算核查](references/evidence-checks.md) 中对应内容。
- 默认完成可编辑 `.docx`；用户只要提纲、纯文本或指定章节时，仅完成该范围。PDF、PPT、单独的学习资料不自动追加。
- 用户新给的作业要求、字数、署名、文献范围和模板优先于这里的默认值。信息足够就直接写，不重复询问已经给出的信息。
- 四篇样稿的关键规则已归纳在参考文件中，正常使用不需要寻找原工作目录或重新读取所有样稿。

## 先读文献，再组织论证

1. 确认主文献题名、作者、期刊、年份、卷页或文章号、DOI，以及是否获得正文、图表和 Supporting Information（SI）。对有修订的 Word，结合插入、删除、公式、图表与批注读取，不能只用 `paragraph.text` 判断最终内容。
2. 用户提供 PDF 和 SI 时优先读这些材料；只提供 DOI 或链接时先获取可访问的原文。正文或关键 SI 无法取得时，明确缺失范围；只基于实际读到的部分交付有范围说明的草稿，不把摘要扩写包装成完整深读。对不依赖缺失材料的部分继续推进。
3. 围绕每个核心问题记录“实验/对照 → 观察与数据 → 作者解释 → 能支持到什么程度”。记录重要数值、单位、条件和正文/SI 图表位置；这个工作记录用于核查，不必另外交给用户。
4. 背景和后续进展只补充与理解本文直接相关的少量资料，核实实际引用的来源。只有参考文献条目而没有读到其内容时，不声称已经读过或验证了该研究。没有查到后续工作就省略该栏目。
5. 以原论文发表时的问题和技术背景评价创新；需要今天的视角时，另作清楚区分。

## 默认栏目及顺序

开头直接排文献信息，不另加装饰封面或目录：中文题名 → 英文原题 → 原论文作者 → 期刊、年份、卷页/文章号 → 报告人姓名与学号。

1. 摘要（忠实翻译时可标“摘要翻译”；原文无摘要时标“摘要（据全文概括）”）
2. 研究背景
3. 论文研究意义&想要解决问题
4. 研究工作的仪器和方法
5. 研究思路
6. 研究内容
7. 论文工作的结论
8. 论文亮点
9. 后续研究（有经过核实且直接相关的工作时才加入）
10. 评论与体会
11. 参考文献

栏目职责见风格参考。正文以解释连贯的段落为主；研究问题、实验步骤、结论和评论可用普通编号。不要把同一段结果在摘要、内容、结论和亮点四处照搬。

## 保留个人风格

- 中文自然、具体，专业名词首次出现写中文、英文全称及缩写，后文统一简称。解释仪器在本研究中究竟测什么、为什么选它、解决什么问题，而不是堆砌术语。
- “研究思路”重建作者怎样发现问题、选择方案、设计对照、跨过障碍、形成结论；“研究内容”写实际怎么做、观察到什么。
- “论文亮点”解释设计巧在哪里、比什么方案好、由什么证据体现。保持好奇心，避免“开创性”“完美证明”等无依据赞语。
- “评论与体会”是特色部分。优先深入讨论少数具体问题：图表里的不一致、对照是否充分、噪声和误差、实验条件、模型假设、应用边界或可验证的新设想。不给每篇文章硬凑相同数量的优缺点。
- 每条重要评论尽量包含：具体证据 → 判断及理由 → 替代解释或局限 → 可行的验证办法。批评前检查正文和 SI 是否已有回答；额外实验的要求要与论文目标、文体及可行性相称。
- 可以在个人评论中用“我认为”“我注意到”“由此联想到”，并明确哪些是推测。联系课程或个人实验经历只能使用用户已提供的事实，不挪用样稿中的过去经历作为新报告的亲身经历。

## 证据与成稿约束

- 用自然表述区分直接观察、作者解释、报告中的计算和自己的设想；不必把证据标签贴满正文。不能将共定位写成直接观察到了化学键完整，也不能将拟合组分比例直接写成人口或空间区域比例。
- 重要数字回到原文或 SI 核对，保留条件、误差和比较基准。自己算出的结果写出输入、公式、单位、假设，不能冒充作者报告值。
- 保留关键原图或清晰裁图，标注报告图号与原文/SI 图号；图后解释其作用。自绘示意标为示意，不能替代实验数据。能重建的简短表格用可编辑表格，数学推导用 Word 原生公式，化学式用正确上下标。
- 文内用 `[1]`、`[2,3]` 等数字引用，对应文末条目；核实实际使用的条目，不照搬旧报告的参考文献，也不编造 DOI、页码、题名或后续研究。

## Word 与交付检查

制作 DOCX 时使用当前可用的 Documents 工作流，具体版式以 [栏目与风格](references/style-guide.md#word-版式) 为准。默认交付无 Word 批注、无修订痕迹的干净版本，不复制或新建教师点评，不把教师意见写进正文。正文中的“评论与体会”仍是报告者对文献的分析，应保留，不能与 Word 批注混淆。不要复制旧稿中的黄色高亮、旧数据或残留文字。

完成后检查两类问题：

- 内容：栏目职责分明；主文与 SI 支持关键论断；评论不是摘要复述；计算及单位可复核；新想法没有混入作者结论；参考文献与图表编号对应。
- 成品：渲染并查看实际页面，核实页眉、题名、英文空格、公式、上下标、图注、跨页与参考文献；不以 XML 或字符检查代替视觉检查。另做结构检查确认没有批注内容、批注锚点或未处理的修订，不能仅凭预览中未显示批注判定已清除。重点修复孤立标题、脱离图像的图注、末页仅一行文献、大块无意义留白。

只交付用户要求的文件，简述完成内容和影响理解的材料缺口。不要在正常成稿里插入工具日志、占位符、核查清单或“AI生成”自述；需要说明的来源或研究局限保留在合适位置。无法完成渲染时如实说明，不宣称版式已验证。
